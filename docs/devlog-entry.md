# MusicSync：把「我喜欢」的歌自动补齐到本地

一个跑在 Windows 上的小工具：定时读你在音乐平台的歌单，跟本地曲库比一遍，缺哪首补哪首。

## 为什么做这个东西

我的歌单一直在长，本地曲库一直没跟上。每次想起来手动点一遍，都是同一套动作：翻歌单、找哪首没下过、切平台、重命名。做过三次之后就烦了，索性让它自己干。

最初的版本只有一个 `netease.py` 和一个 `while` 循环。后来把「跑完给我个提示」也加上了，因为最难受的不是下载慢，是不确定它到底跑没跑。再后来有人问能不能换成别的平台，就有了第二、第三个适配器。

## 它现在能做什么

- 读歌单、对账、补缺，已有的直接跳过
- 三个平台可选做主来源，主平台没有版权的歌可以换源补
- 不用手填 cookie：网易云直接读客户端本地登录态，其它平台读浏览器里已经登录过的状态
- 注册 Windows 计划任务，每周 / 每天 / 每隔 N 小时跑一次；跑完右下角弹个小窗汇报结果
- 自动把网易云、QQ音乐客户端里的下载成品归到曲库目录
- 一条命令自检：依赖、目录、网络、登录态、计划任务，哪里缺了都会说

## 下载与使用

（占位：GitHub Releases 页面和安装说明补齐后替换。）

大致三步：装 Python 依赖 → 跑 `python -m music_sync settings` 填一遍 → 用 `scripts/install_task.ps1` 注册计划任务。README 里有完整步骤和每个平台拿登录态的办法。

## 几个值得说的实现

**多平台适配器架构。** 每个平台是一个 `BaseAdapter` 子类，只实现「拉歌单」「取下载地址」两件事，剩下的重试、跳过已存在、失败归集全在 `sync.py` 里统一处理。`platforms/__init__.py` 维护一个注册表，加平台不用改主流程——汽水音乐先只放了占位适配器，也是靠这个结构才敢先占位再补。

**歌名对账算法。** 下载下来的文件按 `歌手 - 歌名.mp3` 命名，对账的时候就按这个格式反解回「歌手 / 歌名」再去歌单里比对。麻烦在于同一首歌在两边可能写成 `周杰伦 - 晴天` 和 `晴天 - 周杰伦`，或者一边带 `(Live)` 一边不带。做法是先把文件名和元数据都拆成候选对，再做规范化（去全半角差异、去多余空白、括号版本词单独提出来当附加特征），只有「歌手+歌名」都能对上且版本特征不冲突才算命中。宁可多下一次，也不要因为模糊匹配把不该下的删掉或者漏掉。

**计划任务和右下角提示窗。** 计划任务用 `schtasks /Create /XML` 注册——不是因为它优雅，是因为 `/SC` 那套开关设不了「工作目录」和「错过就开始」，而这两项缺一个，任务在别的机器上就会跑出怪事。脚本幂等，先删再建，改时间就是重跑一次。提示窗是个独立的 `pythonw.exe` 进程，只活几秒，主同步进程下完就退出，不留常驻后台。

**跨终端自检。** `python -m music_sync check` 把所有「我这里能跑、换台机器就炸」的东西挨个查一遍：Python 版本、依赖能不能 import、曲库目录能不能写、配置里有没有残留的占位值、各平台登录态、计划任务装没装。每项给 `ok / warn / fail` 和一句人话说明。这条命令的用处是省掉「你那边报什么错」这个来回。

## 说明

- 汽水音乐只有占位适配器，不能登录、不能下载，只占个平台位。
- QQ音乐和酷狗的下载接口我没有在真机账号上完整验证过，是按公开接口写的，接口一变就可能失效。
- 只支持 Windows，毕竟依赖计划任务、DPAPI 和 `pythonw.exe`。
- 只用来管理自己账号的歌单。

代码不复杂，总共几千行，`music_sync/` 下面按模块拆开了，想改哪个平台直接照 `netease.py` 抄一份就行。
